# duorou 记忆数据结构 v0.2：由证据支持的事件、陈述与任务视图

日期：2026-11-23。范围：独立于 Rolling Memory 的数据层设计与 SQLite 验证原型。该文档同时描述目标架构和当前原型；具体实现状态以 README 与实际 SQL 为准。

## 1. 设计结论与问题定位

将原来的 `{id, scope, text}` 平面文本集合，扩展为**带来源、时间、身份归属和派生关系的证据网络**。原文是可追溯基础；事件、事实陈述、实体、意图、程序和工作集是不同用途的视图。它们并行存在，不是原文逐级压缩后被永久丢弃的流水线。

当前公开数据基线说明了为什么值得做这一改动：LoCoMo 的 BM25 在 1,527 个可评问题上 Recall@20 为 62.03%、AllHit@20 为 56.84%；在 278 个 multi-hop 问题上，Recall@20 为 33.51%、AllHit@20 为 14.75%。这些数字来自之前保存的检索评测，随包附有原始汇总快照。它们说明当前方案常常没有找齐分散证据，不能证明事件图一定能解决问题，也不是生成答案准确率。

本次目标是让数据能够准确表达以下问题，给后续检索提供可用线索：

- 谁在何时、什么情境下，说了或做了什么？
- 信息来自原始观察、本人声明、转述、工具结果，还是模型推断？
- 哪些片段描述同一次活动，哪些只是内容相似的不同活动？
- 某种状态在什么时间有效，后来由什么信息补充、修正或撤回？
- 当前任务需要哪几条证据，这些证据是否真的已经交付给 Agent？

## 2. 科学依据与工程边界

详细论文与证据类型见 [SCIENTIFIC_BASIS.zh.md](SCIENTIFIC_BASIS.zh.md)。这里采用的是功能启发，不宣称数据库是生物大脑的复刻。

| 认知机制 | 对数据层的启发 | 不能据此推导 |
|---|---|---|
| 互补学习系统：具体经历与结构化知识的学习分工 | 原始经历快速写入；归纳结果独立版本化，并保留来源 | 海马等于缓存、皮层等于某种数据库；摘要可替代证据 |
| 事件分割与层级事件表征 | 保存事件边界、上下文、参与者角色和成员片段 | session 或固定 token chunk 天然等于认知事件 |
| 关系绑定与部分线索提取 | 从种子证据找同一事件的其他已保存证据 | 可以生成不存在的“关联事实”填补缺口 |
| 模式分离 | 相似经历有独立发生实例与身份消歧 | 文本相似就应合并实体或事件 |
| 目标维持和认知控制 | 工作集根据当前目标与预算动态选择长期记忆 | 存在一个可直接采用的生物 token 上限 |
| 前瞻记忆 | 计划、触发条件、期限和完成证据单独表示 | 有意图等于已完成，也不自动授权执行 |
| 来源监控与记忆更新 | 显式记录出处、推断性质、版本与时间 | 人脑直接存储 source_id；双时态表是脑的实现方式 |

人类记忆会重建、混淆和遗忘。软件可以有选择地采用有帮助的组织原则，同时用不可静默改写的来源、明确的类型和审计记录减少这些错误。这里不引入基于文风的稳定人格、敏感身份或心理状态推断。

## 3. 逻辑数据模型

### 3.1 证据基础

`source` 保存实际接收的一个来源版本。对话消息、文档段落和工具结果都可接入，但必须携带来源类型、外部标识、原文、内容哈希、接收时间和作用域。

`evidence_span` 指向该版本原文的精确片段。原型采用 **Unicode code point、从零计数、左闭右开区间**。它不是 UTF-8 字节偏移、JavaScript UTF-16 索引，也不是用户感知字符数。原文不做隐式规范化；任何清洗版本另建投影，并记录映射。这样证据定位不会随抽取器重跑而漂移。

原文的不可原地更新，是避免抽取结果覆盖历史证据的约束；它不表示必须永久保存。明确删除可以发生，并需要联动索引、派生视图和缓存。SQLite 文件/WAL/备份中的物理擦除另属存储运维工作。

### 3.2 事件和经历

`event` 表示一次具体活动或一个待确认的结构分组，具有发生实例 ID。目标结构包含活动类型、参与者及角色、对象、地点、时间、目标、结果和发生状态。`event_membership` 将原文 span 连接到事件。

同一段原文可以涉及多个事件；同一事件也可以跨多个会话。上层 episode 可以包含子事件，但需要防止循环引用，并保留边界依据和分割版本。

原型的 LoCoMo 导入只依据公开数据中的 session 结构建立 `kind=source_session`、`status=provisional` 的分组。**这不是语义事件识别。** `semantic_event` 留给以后独立验证的分割器。当前没有自动生成动作、因果、参与角色或事件摘要。

### 3.3 陈述与语义知识

`claim` 保存可归属的一条陈述，基本形式为：

`主体 + 谓词 + 有类型的对象 + 极性 + 模态 + 声明者 + 有效时间 + 来源`

对象可以是文本、数值、布尔值、实体引用或结构化 JSON。带量纲的数据还应在领域扩展中规定单位和精度，不能把“30”“30℃”和“30分钟”当作同一种值。

需要把以下维度分开：

- `polarity`：肯定或否定。
- `modality`：描述现实状态、计划、假设、条件。
- `epistemic_mode`：来源陈述、工具观察、模型推断、引用。
- `status`：候选、活跃、争议、撤回、被替代。
- `extraction_confidence`：抽取器对这次结构化是否准确的估计。

SQL 中的 `modality=actual` 表示来源把内容表述为已发生/现实状态，不是系统证明其客观真实。`status=active` 也只表示当前使用的记录状态。来源可信度、事实独立印证程度、抽取置信度和查询相关度不能共享一个含糊的 confidence 字段。未经校准的模型分数不是事实为真的概率。

跨多个经历形成的偏好、规则或概括，也属于有来源的语义陈述。单次明确陈述可以形成候选知识；无需规定出现三次才记录。反过来，同一原文被十个 Agent 转述，不构成十份独立证据。未来需以来源根节点/派生血缘去重，而不是计消息数。

### 3.4 实体与身份

`entity` 是作用域内的对象；`mention` 是原文中实际出现的名字、称谓或代词；`alias` 是带证据的候选名称映射。这三者分开。

至少区分四种身份：

| 身份 | 含义 | 从哪里确定 |
|---|---|---|
| principal | 通过 MCP/服务认证的调用主体 | 可信认证层 |
| source/author | 消息、文档、工具输出的来源 | 接入元数据与来源证据 |
| speaker / asserted_by | 谁在说这句话、作出这个陈述 | 消息角色、引用结构与证据 |
| subject / actor | 说的是谁、由谁执行活动 | 原文实体与角色分析 |

相同姓名不自动合并；不同 conversation 的同名 speaker 也不自动共享身份。原型只使用 LoCoMo 的 source speaker 元数据建立 scope 内 `source_bound` 实体，不将其称为现实世界身份已核验。实体绑定、跨 scope 共享、团队成员关系应由可信系统或明确的审核流程决定。

多个 Agent 需要共享项目记忆时，使用明确的共享 scope 与权限；各 Agent 的工作集仍按任务隔离。Agent 生成的摘要要保留派生身份，不应变成“用户亲口说过”的记忆。导入接口读取的是明确接入的来源，不需要后台扫描其他 Agent 的会话目录。

### 3.5 意图、程序和工作集

`intention` 表示未来事项：责任人、动作说明、触发条件、期限、状态与证据。到期只说明期限已过，不是完成。完成需要相应证据。此表不包含调度执行权限，也没有自动发消息或调用外部服务的效果。

`procedure` 目标模型表示可复用做法：输入、前置条件、步骤、输出、适用范围、版本及实际验证记录。教程中的建议先作为来源/陈述，经过执行和验证才可标为已验证程序。原型尚未实现程序记忆表和执行器。

`working_set` 保存某个任务当下选择的证据引用、预算和过期时间，不是另一份独立事实库。工作集条目淘汰只改变当前上下文，不能删除长期来源。SQL 已有引用结构；目标解析、证据选择、token 计算、TTL 执行和任务隔离的服务逻辑仍待实现。

## 4. 数据层打标签的方法

### 4.1 一等字段与附加标签分工

身份、作用域、认证、模态、时间、状态和版本是有类型字段或关系，不能全部塞到任意 JSON tags 中。附加标签采用 `namespace + key + typed value` 受控词表，帮助主题检索、过程解释与质量审查。

| 维度 | 存储方式 | 示例 | 索引用途 |
|---|---|---|---|
| 表征类型 | 表/枚举 | source、event、claim、intention | 选择查询通道 |
| 实体与角色 | FK/关系表 | actor、owner、recipient | 找到谁做什么 |
| 时间 | 结构化时间和原始字符串 | 发生区间、有效区间、时区状态 | 历史与当前状态 |
| 来源与认识状态 | 字段/证据关系 | source_assertion、model_inference | 判断归属和证据性质 |
| 任务 | task/goal 引用 | 项目、待办、工作集 | 当前目标筛选 |
| 主题与领域 | 受控标签 | domain.topic、domain.activity | 粗筛与解释 |
| 抽取质量 | 受控标签/字段 | provisional、unknown | 决定是否只作软线索 |
| 权限与保留 | 可信配置和关系 | scope_grants、retention policy | 强制访问边界 |

不能从“谈到了项目 A”推导“项目 A 所有成员可以阅读”。权限由可信身份与授权关系决定，不由内容标签决定。

### 4.2 标签的来源合同

原型标签字段：目标对象、词表定义、JSON 有类型值、来源 span、`origin`、状态、抽取器版本、抽取置信度。

`origin` 与 SQL 一致：`metadata / human / rule / model`。它表达生成标签的方法，不等同于陈述的真伪或来源信任级别。`human` 不表示已经授权；`rule` 也不保证判断正确。模型标签必须有证据 span；候选标签不能在默认检索路径中当成确定事实。

附带的 `schema/tag_registry.json` 是建议的版本化词表。`schema/annotation.schema.json` 是与 SQL 标注字段对齐的输入结构合同。JSON Schema 负责形状检查，SQLite 外键/触发器负责目标和基础类型；词表语义、授权、跨度是否真正支持标签，仍需服务校验和评测。

缺少标签代表未观察/未抽取，不等于 false。对不确定的实体或主题，允许保留候选/unknown。低置信度主题标签主要用于排序或扩展；若把它们作为硬过滤条件，错误标签会直接造成漏检。

## 5. 时间、冲突与修订

两个主时间轴必须独立：

1. **valid time**：陈述描述的状态在世界中何时有效。
2. **recorded time**：系统在何时持有这一版本的理解。

此外保存原始来源时间、接入时间、时间精度、时区是否已知，以及“明天”等相对时间的原句与解析依据。原型时间戳使用 Unix 微秒整数，区间为左闭右开。LoCoMo 没有可靠提供的时区不会被补成 UTC；原始 session 时间保留，语义时间待后续解析。

示例为解释设计的虚构内容：11 月 1 日说“我现在住北京”，11 月 15 日说“我 11 月 10 日搬到了上海”。旧陈述和新陈述可在各自的有效时间内成立；11 月 11 日系统可能还不知道搬家。要分别回答“11 月 11 日住哪里”和“11 月 11 日我们当时知道住哪里”。

修订应当追加版本并链接 `supports / contradicts / supersedes`。不能仅根据录入更晚就认定更真。条件不同、主体不同、时间不同的两个陈述也不必然矛盾。

原型对 claim 的内容禁止原地变更，只允许关闭当前 `recorded_to_us` 后追加新版本；同一 claim 的记录时间不能重叠。关闭与追加需要服务使用同一事务。完整的事实裁决、相对时间解析、证据独立性和自动矛盾发现不由 DDL 自动完成。

## 6. 索引设计：每个索引对应一种查询路径

| 查询需求 | 逻辑索引 | 原型状态 |
|---|---|---|
| 名称、编号、原句、关键词 | 原文 FTS/BM25 | SQLite FTS5 已实现，仅原文 |
| 某人/项目相关来源 | scope + speaker/entity + time | speaker 来源索引已实现；全文实体抽取未实现 |
| 别名查询 | scope + alias + status | 表与 B-tree 已实现，未自动构建实体链接 |
| 同一事件的关联证据 | event→span 与 span→event | 已实现；仅导入 session 结构 |
| 某对象某时状态 | scope + subject + predicate + modality + valid time | claim 索引已实现，语义抽取未实现 |
| 支持、冲突、替代关系 | 正向主键 + 反向邻接索引 | claim 关系已实现；通用图遍历未实现 |
| 主题筛选 | scope + namespace + key + value + status | 标签查找索引已实现 |
| 待办/期限 | scope + state + due time | 意图表/索引已实现，无调度器 |
| 语义近似表达 | 向量 ANN + 元数据预过滤 | 设计项，尚未实现 |
| 纠错/删除影响 | source→span→派生对象的反向关系 | 部分 FK/级联已实现，跨系统失效传播未实现 |

这些是逻辑访问路径，不要求使用不同数据库。第一阶段使用一个结构化数据库和全文索引即可。向量组件以后独立加入，记录模型、版本、维度、归一化方法和被索引内容哈希。事件、原文、claim 不同粒度的相似度不能未经校准直接比较；可用分通道候选和秩融合后统一重排。

在大规模场景，B-tree 对两个时间边界的筛选能力也要通过查询计划和负载验证；时间区间查询不因为列都在复合索引中就一定高效。高频稳定路径优先索引，避免给每个可选标签都建独立索引造成写放大。

### 权限与统计隔离

认证得到的 principal 与授权集合来自服务，不信任模型填写的身份。所有全文、结构、向量和关系扩展路径都要限制到同一可见集合；派生内容需要继承其使用来源的可见性。

原型具有 scope 复合外键和服务函数内的 scope_grants 校验，能够验证指定接口拒绝无权读取。但 SQLite 没有数据库行级安全：持有 DB 文件或可任意执行 SQL 的人可以绕开接口。当前使用一个全局 FTS 索引；虽然结果过滤 scope，词频统计仍共享，不能声称实现了租户统计隔离。生产系统需考虑按 scope/租户分区索引、独立统计与缓存分区。

### 分词与语言

原型 FTS 使用 `unicode61`，导入验证来自英语 LoCoMo。这里不宣称已验证中文检索质量。中文业务应固定可复现的分词器，比较词粒度/字符 n-gram 及语义索引，单独报告中文查询的结果、编号保留和分词版本。不能将英语检索结果直接外推到中文。

## 7. 检索和工作记忆装配

目标检索过程如下。当前包实现数据层，不含整套检索策略。

1. 从认证层取得 principal 与可见 scope，读取当前 task 的目标、约束和预算。
2. 把查询解析成候选实体、时间、事件/陈述类型和所需证据槽位；不确定槽位保留候选。
3. 并行生成全文、结构和可选向量候选，记录候选来自哪个通道。
4. 从种子沿已保存的事件/实体/证据关系有限扩展；限制跳数、每种边扇出和总候选量。
5. 检查角色、时间、模态和来源，保留与问题相关的冲突，去除重复来源血缘。
6. 在固定叶子证据数量或实际文本 token 预算内，兼顾相关性与证据覆盖；不让同义重复片段占满上下文。
7. 返回证据包与未解决项，再把选择结果写入当前工作集引用。

这里的“补全”只找回已经保存的关联内容。不能把模型猜测生成的桥接句当成原始证据。共现不等于因果，`before` 也不等于 `caused_by`。来源声称的因果可以保存为归属该来源的 claim；没有依据时仍保留未知。

节点通常有不同的扩展价值。频繁出现的人物或项目可能连接数千条内容，不能沿它把全部邻居导入工作集。事件实例、参与角色、时间窗、任务约束应联合限制扩展。初始一至两跳只是待评测工程配置，不是神经科学常数。

检索评分与真实性分离。任务相关性、槽位覆盖、时间匹配、新颖性和成本可用于选择；权限是硬约束，事实支持关系是返回的证据属性。访问次数可以优化缓存和检索优先级，不直接提高 claim 的事实可信度。

## 8. 写入、归纳和删除的一致性

同步写入路径：鉴权 → 来源版本/幂等校验 → 原文和 span → 确定性元数据 → 原文索引 → 返回已提交 revision。SQL 原型的原文与 FTS 由事务触发器同步。来源哈希应由服务计算，DDL 只校验格式，不证明内容和哈希相符。

异步派生路径：明确版本的抽取器读取证据 → 候选实体/事件/claim/tag → 验证来源位置与结构 → 发布可见 revision。抽取器升级应能重跑而不静默改变旧记录的含义。派生任务失败不能阻止原始证据可检索；新增语义结果何时可见需成为可观测指标。

归纳只创建来源明确的摘要、概括或规则，不默认删除对应经历。保留支持和反例；重复来源去重；变化通过版本表达。来源删除时，依赖该来源的内容需要失效或重算，不得继续把失去证据的摘要当成已支持。

遗忘至少分成五种操作：检索降权、冷热迁移、业务失效、撤回纠错和实际删除。不同操作的权限、语义、审计和后果不同。当前原型只验证所建表及 FTS 的部分级联删除，不承担所有外部系统的数据生命周期管理。

## 9. 与 MCP 和现有评测工具的关系

已经存在的 `memory-query-bench` 是**压测控制 MCP**；`public_memory_bench.target` 是用于公开数据评测的检索目标。它们的代码不在这轮修改。

本包是拟由检索目标使用的下一版数据层，尚未部署成新的 MCP server。建议的业务工具边界为：

| 工具草案 | 作用 |
|---|---|
| memory_ingest | 接收明确来源，写入原文，返回 revision/派生进度 |
| memory_search | 在任务与证据预算下检索，返回证据包 |
| memory_get_evidence | 取回授权来源及精确 span |
| memory_timeline | 按有效时间/记录时间读取实体或事件历史 |
| memory_explain | 展示命中标签、关系路径、版本和来源 |
| memory_review / memory_forget | 明确的纠错/合并/删除操作，各自鉴权 |

以上是 API 设计，不是声称现在这些工具已注册。principal 应由可信会话提供，不能把 `principal_id` 作为模型可自由填写的认证参数。查询可以指定 scope 意图，但仍必须验证授权。stdio 本地部署也需要按实际进程/用户信任边界配置，而不是因为采用 MCP 就自动获得安全隔离。

证据包应有实际返回的叶子文本、source/span ID、相关 claim 的模态/时间/来源、冲突、未解决槽位、索引版本和检索轨迹。只返回抽象节点及大量 source_id，不等于向调用 Agent 交付了证据。

## 10. 优先级与判定标准

第一步完成可靠数据骨架：证据/span、来源归属、scope、时间版本、类型标签和索引。本次交付涵盖其 SQLite 原型和真实公开数据导入验证。

第二步用确定性元数据和事件成员路径接入现有目标，再逐步加入实体角色、时间解析和受控关系扩展。对每一步单独测量质量与成本。

第三步才加入模型抽取、语义概括、程序记忆和自动归纳。只有当同等实际证据预算下，公开数据多跳证据完整率改善，且错误身份关联、时间/模态混淆、成本和隔离问题可控，才认为这些结构产生了工程收益。完整实验协议见 [EVALUATION.zh.md](EVALUATION.zh.md)。

这轮没有新 Recall/AllHit 增益结论，也没有“已把性能压榨完”的结论。SQL 约束、导入成功和语义检索效果是不同的验证对象。
